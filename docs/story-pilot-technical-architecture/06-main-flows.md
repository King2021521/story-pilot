# 主流程设计

## 流程总览

Story Pilot 的核心闭环是：

```text
创建项目
  │
  ▼
建立故事圣经
  │
  ▼
设计人物、世界观、剧情线和伏笔
  │
  ▼
生成或编写章节
  │
  ▼
审阅、润色、修订
  │
  ▼
提取记忆候选
  │
  ▼
用户确认 canon
  │
  ▼
更新图谱和检索索引
  │
  ▼
继续下一章
```

这个闭环的关键是：AI 参与产出，但用户掌握 canon。

## 流程一：新建项目

### 用户目标

用户希望从题材和初始想法开始，快速形成可持续创作的项目空间。

### 流程

```text
用户点击新建作品
  │
  ▼
选择题材、篇幅、目标读者、风格、创作目标
  │
  ▼
系统创建 project directory
  │
  ▼
初始化 global project_index
  │
  ▼
初始化 project.sqlite
  │
  ▼
初始化 graph.kuzu
  │
  ▼
创建默认 work、第一卷、故事圣经初始记录
  │
  ▼
进入项目工作台
```

### 后端动作

- 创建项目目录。
- 执行项目数据库 migration。
- 写入 `projects`、`works`。
- 写入 `domain_events.project.created`。
- 创建空图谱 schema。
- 写入最近项目。

### 失败处理

- 目录创建失败：提示用户选择新位置。
- migration 失败：删除未完成项目目录或保留诊断文件。
- graph 初始化失败：允许项目打开，但标记图谱不可用并提示重建。

## 流程二：故事圣经生成

### 用户目标

用户希望系统根据题材和初始想法生成世界观、人物、主线冲突和风格方向。

### 流程

```text
用户在项目首页点击“生成故事圣经”
  │
  ▼
填写或选择项目 brief
  │
  ▼
创建 StoryBibleDraft work_order
  │
  ▼
ContextBuilder 读取预设库和项目 brief
  │
  ▼
ModelGateway 生成故事圣经草案
  │
  ▼
ReviewEngine 检查完整性和内在矛盾
  │
  ▼
ArtifactService 保存草案
  │
  ▼
MemoryExtractor 生成候选人物、世界规则、故事线
  │
  ▼
用户选择采用哪些内容
  │
  ▼
ApplicationService 写入正式设定
  │
  ▼
GraphProjector 更新人物、规则、故事线图谱
```

### 产物

- `artifacts.kind = story_bible_draft`
- `memory_candidates`
- `characters` draft 或 canon
- `world_rules` draft 或 canon
- `plotlines` draft 或 canon

### 关键约束

- 故事圣经草案不能一次性全自动变成 canon。
- 用户可以逐项接受、编辑、拒绝。
- 被接受项写入正式表，并生成 domain events。

## 流程三：人物名称和元素生成

### 用户目标

用户想快速生成符合题材、文化背景和风格的名称或设定元素。

### 流程

```text
用户在人物表单点击“生成名字”
  │
  ▼
系统读取题材、地域、时代、命名风格
  │
  ▼
ElementGenerationWorkflow 生成候选
  │
  ▼
检查项目内重名和近似名
  │
  ▼
返回候选列表
  │
  ▼
用户选择一个候选
  │
  ▼
填入表单，不自动保存
```

### 技术要点

- 名称生成可以优先走本地规则和词库。
- 需要更复杂风格时再调用模型。
- 结果需要标记来源和风格解释。
- 不应把未选择候选写入正式人物表。

## 流程四：大纲生成

### 用户目标

用户希望从故事圣经生成可执行的卷纲和章纲。

### 流程

```text
用户选择“生成大纲”
  │
  ▼
选择范围：全书、某卷、某条故事线
  │
  ▼
创建 OutlineGeneration work_order
  │
  ▼
读取 story bible、人物、世界规则、已有剧情线
  │
  ▼
图谱查询冲突、伏笔和人物关系
  │
  ▼
模型生成大纲
  │
  ▼
规则检查节奏、缺口和因果链
  │
  ▼
保存 outline artifact
  │
  ▼
用户应用
  │
  ▼
写入 volumes、chapters、plotline_nodes、foreshadowing_events
```

### 应用方式

用户可以：

- 全部应用。
- 只应用卷结构。
- 只应用某几章。
- 编辑后应用。
- 保存为备选方案。

## 流程五：章节草稿生成

### 用户目标

用户希望基于章纲和已确认设定生成章节正文。

### 流程

```text
用户打开某章
  │
  ▼
点击“生成草稿”
  │
  ▼
系统检查章节状态和锁
  │
  ▼
创建 ChapterDraft work_order
  │
  ▼
构建章节上下文包
  │
  ├── 本章目标
  ├── 前后章节摘要
  ├── 当前人物卡
  ├── 世界规则
  ├── 相关伏笔
  ├── 图谱邻域
  └── 风格规范
  │
  ▼
模型流式生成正文草稿
  │
  ▼
保存 draft artifact
  │
  ▼
连续性检查
  │
  ▼
提取记忆候选
  │
  ▼
用户对比当前正文和草稿
  │
  ▼
用户应用、部分应用或拒绝
```

### 写入规则

- 生成完成后只写 `artifacts`。
- 应用草稿时写 `chapter_versions` 和 `chapters.content`。
- 应用后写 `domain_events.chapter.updated`。
- 记忆候选仍需用户确认。

### 冲突处理

如果用户在 AI 生成过程中手动修改了章节：

- 通过 `chapters.version` 检测版本冲突。
- 提供三种选择：覆盖、另存为版本、合并为补丁。
- 默认不覆盖用户新改动。

## 流程六：选中文本润色

### 用户目标

用户希望对编辑器中的一段文本做局部改写。

### 流程

```text
用户选中文本
  │
  ▼
Cmd+K 或浮动工具栏选择润色动作
  │
  ▼
系统读取选区、段落前后文、风格规范
  │
  ▼
模型返回 patch proposal
  │
  ▼
UI 展示 diff
  │
  ▼
用户接受或拒绝
  │
  ▼
接受后写入章节版本
```

### 技术要点

- 对局部文本优先返回 patch，不返回整章。
- patch 应包含 anchor 和原始文本 hash，避免错位应用。
- 小改动可不提取记忆，除非引入事实变化。

## 流程七：连续性检查

### 用户目标

用户希望知道某章或某卷是否和已有设定矛盾。

### 流程

```text
用户点击“连续性检查”
  │
  ▼
选择检查范围
  │
  ▼
系统读取 canon memory、图谱关系、章节内容
  │
  ▼
规则检查
  │
  ▼
模型审阅
  │
  ▼
合并重复问题
  │
  ▼
生成 review artifact
  │
  ▼
看板显示问题和建议
```

### 问题类型

- 事实矛盾。
- 时间线矛盾。
- 人物动机不足。
- 人物声线不一致。
- 世界规则冲突。
- 伏笔未支撑或未回收。
- 章节目标缺失。

## 流程八：记忆确认

### 用户目标

用户希望快速确认哪些新事实进入正式设定，哪些只是草稿信息。

### 流程

```text
系统生成 memory_candidates
  │
  ▼
右侧看板显示待确认记忆
  │
  ▼
用户打开候选详情
  │
  ├── 查看来源
  ├── 查看影响对象
  ├── 查看可能冲突
  └── 查看图谱预览
  │
  ▼
用户选择接受、合并、暂存为 hypothesis、拒绝
  │
  ▼
SQLite 写入 memories 和 domain_events
  │
  ▼
GraphProjector 更新 Kuzu
  │
  ▼
SearchIndexer 更新索引
```

### 批量处理

支持：

- 批量接受低风险事实。
- 批量拒绝重复候选。
- 合并到已有记忆。
- 按人物、章节、类型筛选。

## 流程九：图谱重建

### 触发条件

- 图谱 schema 升级。
- projection checkpoint 错误。
- 用户手动诊断。
- 项目迁移后图谱缺失。

### 流程

```text
标记 graph status = rebuilding
  │
  ▼
停止图谱写入
  │
  ▼
备份旧 graph.kuzu
  │
  ▼
创建新图谱目录
  │
  ▼
根据 SQLite 源数据重建节点
  │
  ▼
根据 memories 和 domain_events 重建边
  │
  ▼
运行一致性校验
  │
  ▼
切换 graph status = ok
```

## 流程十：导出作品

### 用户目标

用户希望导出当前作品或选定范围。

### 流程

```text
用户点击导出
  │
  ▼
选择范围、格式和模板
  │
  ▼
系统创建 export work_order
  │
  ▼
读取章节和元信息
  │
  ▼
生成导出文件
  │
  ▼
写入 files 和 artifacts
  │
  ▼
前端显示导出完成
```

### 格式

MVP：

- Markdown。
- txt。

后续：

- epub。
- docx。
- PDF。

## 流程十一：导入参考资料

### 用户目标

用户希望导入世界观资料、设定文档、已有正文或参考片段。

### 流程

```text
用户导入文件
  │
  ▼
FileStore 保存原件
  │
  ▼
解析文本
  │
  ▼
生成 source artifact
  │
  ▼
执行 chunking 和索引
  │
  ▼
可选执行记忆提取
  │
  ▼
用户确认是否加入项目知识
```

### 注意

- 导入资料默认不等于 canon。
- 用户需要明确标记为参考资料、正式设定或待整理资料。
- 外部版权文本需要明确来源标识。

## 流程十二：异常恢复

### 应用退出恢复

启动时：

```text
读取 running 状态 workflow_runs
  │
  ▼
检查最后完成 step
  │
  ▼
按恢复策略标记 queued、waiting_user 或 failed
  │
  ▼
前端展示未完成任务
```

### 模型失败恢复

- 网络错误：允许重试。
- 超时：允许继续或改用更小上下文。
- JSON 解析失败：尝试 repair，一次失败后进入人工查看。
- 内容安全或 provider 拒绝：保存错误，不再自动重试。

### 数据库失败恢复

- 事务失败：回滚并保留工作单状态。
- migration 失败：阻止打开项目，提示恢复备份。
- 图谱失败：降级为 SQLite/FTS 检索，提示重建图谱。
