# 需求分析过程

## 1. 输入理解

用户提出的产品方向是：建设一个真实场景下的小说创作平台 agent，平台一体化托管小说及其他文学作品的创作过程，主打 AI 生成，并结合长期记忆模块提升生成和创作质量。

用户明确提到的核心功能包括：

- 作品管理。
- 创作过程管理。
- 题材选择。
- 世界观设计。
- 人物设计。
- 剧情设计。
- 伏笔和埋伏设计。
- 冲突设计。
- 大纲设计。
- 各类故事线设计。
- 正文编写。
- 润色。
- 校正。

我将其理解为一个面向长篇文学、尤其是网络小说和连载文学的 AI 创作操作系统，而不是一个单点文本生成工具。

## 2. 分析假设

- 目标产品优先服务中文网络文学场景，但架构应兼容传统长篇小说、短篇集、剧本化改编和多语种扩展。
- 创作模式以 AI 生成和 AI 辅助为主，但必须保留人类作者的审美判断、取舍、确认和版本责任。
- 长期记忆不是简单聊天记录，而是作品级、作者级、项目级的结构化创作资产。
- 平台早期目标不是替代阅文、番茄、晋江、Royal Road 等阅读/分发平台，而是先成为创作与生产中枢。
- 对外发布、版权登记、商业化、社区共创可以作为后续阶段，而不是 MVP 的首要目标。

## 3. 资料筛选

参考资料分为五类：

- 网络文学行业报告：用于判断市场规模、网文精品化趋势、常见创作问题和 IP 化方向。
- 经典叙事理论：用于抽取稳定的文学创作要素，如情节、人物、语言、思想、反转、发现等。
- 网络小说/连载创作实践：用于设计章节节奏、更新节奏、读者钩子、爽点推进和长期追读体验。
- AI 写作竞品：用于识别故事圣经、记忆盒、时间线、人物表、世界观库等已有产品形态。
- Agent 与长期记忆论文：用于构建可解释、可演进、可评估的 agent 架构。

完整资料见 [references.md](references.md)。

## 4. 分析框架

本次需求分析采用四层框架：

1. 创作对象层：作品、系列、卷、章、场景、人物、地点、组织、物品、设定、事件、伏笔、主题、风格。
2. 创作过程层：立项、题材定位、世界观设计、人物设计、剧情设计、章节规划、正文生成、修订、审校、发布准备。
3. Agent 能力层：总编、主笔、世界观设计、人物设计、剧情结构、伏笔管理、连续性审校、润色、读者模拟、合规版权等角色。
4. 记忆与质量层：长期记忆、上下文装配、版本记录、质量评分、冲突检测、创作复盘和学习闭环。

## 5. 需求推导路径

需求不是从“AI 能生成什么”开始，而是从“长篇文学创作为什么难”开始：

- 长篇难在一致性：人物前史、动机、能力、关系、世界规则和时间线容易漂移。
- 连载难在持续性：每天/每周更新需要稳定产能、章节钩子和读者反馈吸收。
- 网文难在承诺兑现：题材、爽点、情感线、升级线、悬念线都需要持续兑现。
- AI 写作难在控制：单次生成看似可用，但长程逻辑、风格稳定、伏笔回收和原创表达容易失控。

因此，平台的需求应围绕“可控生成”而非“自由生成”组织：先建立创作资产，再通过 agent 编排和记忆检索生成正文，最后通过审校 agent 与人类确认把有效内容回写为新的作品记忆。
