# 小说创作 Agent 平台需求分析

## 1. 产品定位

小说创作 Agent 平台是一个 AI 原生的长篇文学创作工作台，面向作者、编辑、工作室和 IP 孵化团队，提供从创意立项到正文生产、修订、审校和发布准备的一体化能力。

它的核心目标是：让 AI 不只是“帮我写一段”，而是能在一部作品的整个生命周期里理解作品、记住作品、推进作品、检查作品，并在人的审美和决策控制下持续产出可用文本。

一句话定义：

> 面向长篇文学与网络小说生产的 AI 创作室，核心能力是作品级长期记忆、专业创作流程和多 agent 质量闭环。

## 2. 目标用户

### 2.1 AI-first 网络小说作者

这类用户希望高频产出、快速试题材、快速起量，关注更新效率、章节爽点、读者留存、设定一致性和后续商业化。

核心痛点：

- 创意很多，但难以稳定展开为长篇。
- 前几章能写，几十章后设定和人物容易混乱。
- AI 生成内容容易套路化、同质化、人物扁平。
- 每次对话都要重复背景，生成上下文成本高。

### 2.2 传统作者或严肃文学创作者

这类用户更关注主题、语言、人物复杂性、结构完整性和修改质量，未必追求高速更新。

核心痛点：

- 需要辅助整理材料、人物关系、时间线和结构。
- 需要不同改稿视角，而不是单纯扩写。
- 需要保留个人文风和审美控制。

### 2.3 内容工作室和 IP 团队

这类用户关注多项目并行、团队协同、IP 资产沉淀、系列化生产、审核与版本管理。

核心痛点：

- 多作者、多编辑协作时知识不集中。
- IP 世界观、人物、设定、伏笔难以跨作品复用。
- 需要可追踪的创作决策和版权/合规记录。

### 2.4 编辑、写作教练和内容策划

这类用户不一定直接写正文，但负责选题、评估、诊断、指导和调优。

核心痛点：

- 需要快速看出作品短板。
- 需要对大纲、人物、章节、节奏给出结构化反馈。
- 需要把创作建议变成可执行任务，而不是泛泛评价。

## 3. 核心价值主张

### 3.1 从 prompt 写作升级为作品工程

平台应让作者管理一部作品的全部创作资产：故事圣经、角色档案、世界规则、时间线、章节计划、伏笔表、风格指南、版本分支和审校报告。

### 3.2 从一次性生成升级为长期协作

Agent 应能记住已确认的设定、已发生事件、人物成长、语气偏好和未回收伏笔，并在后续生成中主动引用、避免冲突、提醒遗漏。

### 3.3 从“能写”升级为“可控地写好”

系统必须支持生成前约束、生成中上下文装配、生成后质量评估、人工确认、记忆回写，形成可控闭环。

### 3.4 从文本工具升级为创作团队

一个成熟作品不是一个“写作模型”完成的，而是由总编、策划、人物设计、剧情结构、主笔、审校、润色、读者反馈等多个专业视角共同打磨。平台应把这些视角 agent 化。

## 4. 典型使用场景

### 4.1 新作品立项

作者输入一个初始想法，例如“东方玄幻、低开高走、主角靠记忆碎片破解古神骗局”。平台需要引导完成：

- 题材定位。
- 目标读者。
- 核心卖点。
- 故事承诺。
- 差异化设定。
- 主线冲突。
- 主角欲望与缺陷。
- 前 30 章推进方向。

产出物包括作品立项卡、题材分析、核心梗概、风险提示和下一步创作任务。

### 4.2 世界观设计

作者选择或输入题材后，系统引导构建世界规则，而不是堆砌名词。

必须覆盖：

- 世界运行规则。
- 力量体系与代价。
- 阶层结构与资源分配。
- 历史秘密与现实矛盾。
- 地理、组织、制度、宗教、技术或魔法边界。
- 世界规则如何制造人物选择和剧情冲突。

输出必须进入作品记忆，供后续章节生成自动检索。

### 4.3 人物设计

系统不只生成人物设定卡，还要建立人物作为剧情发动机的能力。

必须覆盖：

- 外在目标。
- 内在需求。
- 恐惧、误信和弱点。
- 能力边界。
- 关系网络。
- 语言风格。
- 成长曲线。
- 关键选择。
- 与主题和主线冲突的关系。

每次正文生成后，系统应能更新人物状态：知道了什么、失去了什么、关系如何变化、承诺是否推进。

### 4.4 剧情、大纲和故事线设计

系统应支持从一句话创意逐步展开为多层大纲：

- 全书主线。
- 分卷主线。
- 阶段目标。
- 章节列表。
- 场景卡。
- 人物弧光。
- 感情线、事业线、升级线、悬疑线、反派线等并行故事线。

大纲不是静态文档，而是可以和正文互相同步：正文发生变化后，系统应提示是否更新大纲、时间线和伏笔状态。

### 4.5 伏笔与回收管理

伏笔应作为一等对象管理，而不是散落在正文里。

每条伏笔至少记录：

- 伏笔名称。
- 埋设位置。
- 表层信息。
- 真实含义。
- 关联人物/地点/物品/事件。
- 预计回收位置。
- 当前状态：计划中、已埋设、强化中、已回收、废弃。
- 风险：过早暴露、过久未回收、与新设定冲突。

生成章节时，系统应主动提示本章适合埋设、强化或回收哪些伏笔。

### 4.6 正文生成

正文生成应从“输入 prompt，输出一章”升级为“基于场景卡和上下文包生成可审阅草稿”。

生成前需要明确：

- 本章目标。
- 本章视角。
- 本章出场人物。
- 本章冲突。
- 本章必须推进的故事线。
- 本章必须遵守的世界规则。
- 本章需要埋设/回收的伏笔。
- 本章结尾钩子。
- 字数、文风、节奏和禁忌。

生成后需要提供：

- 正文草稿。
- 关键改动摘要。
- 与大纲不一致之处。
- 记忆候选回写项。
- 质量评分。
- 可选改写方向。

### 4.7 润色、校正和审校

平台至少需要三类修订能力：

- 文学润色：语感、节奏、意象、对白、情绪递进。
- 网文增强：爽点、钩子、冲突升级、章节结尾、信息释放节奏。
- 连续性审校：人物状态、设定一致性、时间线、伏笔、名称、称谓、能力边界。

修订不能只给“更好版本”，还要说明修改意图和风险。例如：增强节奏可能牺牲氛围；强化爽点可能让人物动机变浅。

### 4.8 创作复盘与学习

每完成一个章节、阶段或分卷，系统应生成创作复盘：

- 本阶段推进了哪些承诺。
- 哪些人物发生了变化。
- 哪些伏笔已埋但未回收。
- 哪些设定被新增或修改。
- 风格是否稳定。
- 读者可能的疑问和期待。
- 下一阶段建议。

复盘结果应进入长期记忆，但只有经作者确认的事实才能进入“正史”。

## 5. 功能需求

### 5.1 工作区与作品管理

- 支持创建作品、系列、宇宙、番外和衍生作品。
- 支持作品状态：创意、设定、筹备、连载中、暂停、完结、修订、发布准备。
- 支持题材、标签、目标字数、目标读者、更新节奏、发布渠道记录。
- 支持卷、章、场景的层级管理。
- 支持作品版本、分支和归档。
- 支持导入已有正文、设定文档、大纲和素材。
- 支持导出 Markdown、DOCX、PDF、纯文本和平台发布格式。

### 5.2 故事圣经

故事圣经是作品的结构化知识中心，至少包括：

- 作品核心：一句话梗概、主题、题材承诺、读者期待、禁区。
- 世界观：规则、历史、地理、组织、阶层、力量体系、技术/魔法、资源。
- 人物：角色卡、关系、成长、语言、秘密、状态。
- 剧情：主线、分线、章节、场景、事件、时间线。
- 伏笔：埋设、强化、误导、回收。
- 风格：叙述人称、语气、节奏、句式偏好、禁用表达、样章。
- 素材：灵感、参考、摘录、图片、设定草稿。

### 5.3 创作流程管理

- 支持作品从立项到正文的流程模板。
- 支持不同类型模板：玄幻、仙侠、都市、言情、悬疑、科幻、现实题材、轻小说、短篇、剧本等。
- 支持任务看板：待设计、待生成、待修订、待审校、待确认、待发布。
- 支持按章节、角色、故事线、伏笔创建创作任务。
- 支持 AI 自动建议下一步任务。
- 支持创作里程碑：前 3 章、前 10 章、首卷、上架节点、完结节点。

### 5.4 AI 生成与协作

- 支持基于场景卡生成正文。
- 支持基于已有正文续写。
- 支持生成多候选版本并对比。
- 支持指定风格、视角、节奏、情绪曲线和章节目标。
- 支持“只提建议不改文”“局部改写”“全章重写”“扩写”“压缩”“换视角”等操作。
- 支持人类确认后再更新正史记忆。
- 支持每次生成的输入上下文、模型、参数、输出和人工修改记录。

### 5.5 质量评估

平台应内置文学与网文双维度质量评估：

- 题材承诺是否清晰。
- 本章是否有目标、阻碍、转折和钩子。
- 人物行动是否符合动机。
- 冲突是否升级。
- 信息释放是否过早或过慢。
- 伏笔是否自然。
- 世界规则是否一致。
- 对白是否区分人物声音。
- 文风是否稳定。
- 是否存在套路化、同质化、空泛设定、AI 腔、重复表达。

评估结果应给出可执行修改建议，而不是抽象分数。

### 5.6 长期记忆

长期记忆应支持四个层级：

- 作者级记忆：作者偏好、常用风格、禁忌、创作习惯。
- 项目级记忆：系列设定、IP 宇宙规则、跨作品角色。
- 作品级记忆：当前作品的正史设定、人物、剧情、伏笔、风格。
- 会话级记忆：当前创作任务的临时意图、草稿和讨论过程。

记忆写入必须区分：

- 正史：作者确认后进入作品事实。
- 草稿：可被引用，但不作为强约束。
- 假设：用于探索分支，不污染主线。
- 废弃：保留历史，但默认不进入上下文。

### 5.7 协作与权限

后续阶段应支持：

- 作者、编辑、策划、审校、运营等角色。
- 作品级权限。
- 评论、批注、审阅、建议采纳。
- 修改记录和责任追踪。
- 工作室多项目视图。

MVP 可以先做单用户，但数据模型应预留协作。

### 5.8 合规、版权和内容安全

平台应支持：

- AI 生成内容标识和生成记录。
- 人类修改痕迹和创作贡献记录。
- 训练/参考素材来源记录。
- 敏感内容和违规内容检测。
- 抄袭、融梗、相似表达风险提示。
- 未成年人、暴力、色情、歧视、政治等内容风险分级。
- 对外发布前的合规检查。

## 6. 数据对象

核心对象建议包括：

- Workspace：工作区。
- Project/Series：项目或系列。
- Work：作品。
- Volume：卷。
- Chapter：章。
- Scene：场景。
- Character：人物。
- Location：地点。
- Organization：组织。
- Item：物品。
- Rule：世界规则。
- Event：事件。
- Timeline：时间线。
- Plotline：故事线。
- Foreshadowing：伏笔。
- Theme：主题。
- StyleGuide：风格指南。
- Draft：草稿。
- Revision：修订。
- MemoryEntry：记忆条目。
- ContextPack：生成上下文包。
- AgentRun：Agent 执行记录。
- ReviewReport：审校报告。

这些对象要支持关系，例如人物参与事件、事件推进故事线、伏笔关联物品、章节承接时间线、规则约束冲突。

## 7. 非功能需求

### 7.1 一致性

长篇创作最重要的非功能要求是上下文一致性。系统应能检测设定冲突、人物状态冲突、时间线冲突和叙述风格漂移。

### 7.2 可追溯

每段正文应能追溯到生成任务、输入上下文、使用的记忆、用户确认和后续修订。

### 7.3 可控性

作者必须能锁定设定、锁定人物行为边界、锁定文风样章、禁止特定剧情方向，并能撤销 AI 对正史的污染。

### 7.4 可扩展

系统应支持从单作品扩展到系列和 IP 宇宙，从单作者扩展到工作室协作，从文本扩展到有声、漫画、剧本和游戏设定。

### 7.5 隐私与资产保护

作品设定、草稿、素材、商业计划和风格样本都是高价值创作资产，需要加密存储、权限隔离、审计记录和清晰的数据使用策略。

## 8. MVP 建议

MVP 不应追求“大而全”，建议优先验证一条闭环：

1. 创建作品。
2. 生成/编辑故事圣经。
3. 设计人物和主线大纲。
4. 规划章节和场景卡。
5. 基于上下文包生成章节正文。
6. 审校一致性、伏笔和风格。
7. 作者确认后回写记忆。

MVP 必做模块：

- 作品管理。
- 故事圣经。
- 人物/世界观/大纲结构化编辑。
- 章节正文生成。
- 伏笔表。
- 记忆回写确认。
- 连续性审校。
- 版本记录。

MVP 暂缓模块：

- 大型社区。
- 阅读分发。
- 商业结算。
- 多人实时协作。
- 自动投稿。
- 全渠道发布。
- 复杂 IP 改编。

## 9. 成功指标

创作效率指标：

- 从创意到可写大纲的时间。
- 单章初稿生成时间。
- 作者采纳率。
- 每章平均修订轮次。

质量指标：

- 连续性错误数量。
- 人物动机冲突数量。
- 伏笔遗忘率。
- 风格漂移率。
- AI 腔/重复表达命中率。

作品推进指标：

- 作品完稿率。
- 连载断更率。
- 每周有效字数。
- 首卷完成率。

用户价值指标：

- 作者留存。
- 单作品活跃天数。
- 故事圣经复用率。
- 人工确认记忆数量。
- 导出或发布准备次数。

## 10. 关键产品原则

- AI 负责高强度生成，人负责审美、价值、取舍和确认。
- 记忆必须结构化、可审计、可撤销。
- 创作流程要帮助作者做决定，而不是用表单拖慢创作。
- 所有生成都应服务故事承诺、人物动机和冲突推进。
- 作品正史必须由作者确认，不能由模型自动篡改。
- 平台要主动对抗套路化、人物扁平化和浅层元素拼贴。
