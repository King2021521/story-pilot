# Agent 与长期记忆架构建议

## 1. 总体架构

平台建议采用“创作工作流编排器 + 多专业 agent + 作品长期记忆 + 质量评估闭环”的架构。

核心链路：

1. 用户提出创作目标。
2. 编排器识别任务类型。
3. 检索作品记忆并构建上下文包。
4. 调用一个或多个专业 agent。
5. 生成草稿、建议或审校报告。
6. 用户确认、修改或拒绝。
7. 系统抽取可记忆事实并等待确认。
8. 写入作品正史或草稿记忆。
9. 形成下一步任务。

这里的关键不是“agent 数量多”，而是每个 agent 有明确职责、输入、输出和质量标准。

## 2. Agent 角色

### 2.1 创作总编 Agent

职责：

- 理解作品定位。
- 拆解创作任务。
- 协调其他 agent。
- 控制范围和优先级。
- 在生成前确认本次任务目标。

典型输出：

- 创作任务单。
- 本轮上下文需求。
- 生成/审校策略。
- 下一步建议。

### 2.2 题材定位 Agent

职责：

- 分析题材类型和读者期待。
- 提炼核心卖点。
- 识别同质化风险。
- 建议差异化方向。

典型输出：

- 题材承诺。
- 读者画像。
- 爽点/虐点/悬念点。
- 竞品风险和创新点。

### 2.3 世界观 Agent

职责：

- 设计世界规则。
- 检查设定一致性。
- 将设定转化为冲突来源。
- 管理力量体系、组织、地理、历史、资源和禁忌。

典型输出：

- 世界规则卡。
- 设定冲突矩阵。
- 信息释放计划。

### 2.4 人物 Agent

职责：

- 构建人物动机、缺陷、欲望和弧光。
- 管理关系网络。
- 维护人物声音。
- 追踪人物状态变化。

典型输出：

- 人物卡。
- 关系图。
- 人物弧光计划。
- 对白风格约束。

### 2.5 剧情结构 Agent

职责：

- 设计全书主线、分卷主线和章节大纲。
- 维护多故事线进度。
- 检查因果链和节奏。
- 设计阶段高潮和转折。

典型输出：

- 全书大纲。
- 分卷大纲。
- 章节列表。
- 场景卡。
- 故事线进度表。

### 2.6 伏笔 Agent

职责：

- 设计伏笔、误导、强化和回收。
- 跟踪伏笔状态。
- 在章节生成前提示可用伏笔。
- 在审校时发现遗忘或冲突。

典型输出：

- 伏笔表。
- 本章伏笔建议。
- 回收风险报告。

### 2.7 正文主笔 Agent

职责：

- 按场景卡和上下文包生成正文。
- 保持视角、文风和章节目标。
- 生成多个候选版本。
- 根据反馈局部改写。

典型输出：

- 章节草稿。
- 场景草稿。
- 局部改写。
- 生成说明。

### 2.8 润色 Agent

职责：

- 改善语言、节奏、动作、对白和情绪。
- 识别 AI 腔、重复表达和空泛概括。
- 按题材目标调整文风。

典型输出：

- 润色版本。
- 修改说明。
- 风格风险提示。

### 2.9 连续性审校 Agent

职责：

- 检查人物、时间线、地点、能力、设定和伏笔一致性。
- 识别新正文与正史记忆的冲突。
- 提出修正建议或记忆更新建议。

典型输出：

- 连续性问题列表。
- 严重程度。
- 证据位置。
- 修复建议。

### 2.10 读者模拟 Agent

职责：

- 以目标读者视角评估章节吸引力。
- 判断钩子、爽点、节奏、情绪回报。
- 提醒潜在弃读点。

典型输出：

- 读者期待预测。
- 疑问列表。
- 弃读风险。
- 下章期待。

### 2.11 合规与版权 Agent

职责：

- 检查敏感内容。
- 检查 AIGC 标识和生成记录。
- 提醒潜在侵权、融梗、素材来源和版权风险。
- 为发布准备提供合规清单。

典型输出：

- 合规风险报告。
- 版权/素材来源提示。
- 发布前检查结果。

## 3. 长期记忆设计

### 3.1 记忆分层

建议采用五层记忆：

- 瞬时上下文：当前对话和当前编辑区域。
- 任务记忆：本轮生成目标、约束、候选结果和临时判断。
- 作品记忆：已确认的设定、人物、剧情、伏笔、风格和正文摘要。
- 项目/IP 记忆：系列、宇宙、跨作品设定、复用角色和世界规则。
- 作者记忆：作者偏好、写法习惯、常用禁忌、默认工作流和审美倾向。

### 3.2 记忆类型

作品记忆不应只有向量文本，应至少包含：

- 实体记忆：人物、地点、组织、物品、概念。
- 关系记忆：人物关系、隶属、敌对、亲密、师承、债务。
- 事件记忆：何时何地发生了什么，谁参与，结果是什么。
- 时间线记忆：故事内时间、章节位置、因果顺序。
- 规则记忆：力量体系、世界规则、限制、代价。
- 伏笔记忆：埋设、强化、回收和状态。
- 风格记忆：叙述方式、人物声音、语言偏好。
- 决策记忆：作者确认过的创作选择和被废弃的方向。

### 3.3 记忆状态

每条记忆必须有状态：

- canonical：正史，强约束。
- draft：草稿，可参考。
- hypothesis：探索分支，只在指定分支使用。
- deprecated：废弃，默认不使用。
- conflicted：冲突，需要人类裁决。

AI 不能自行把草稿升级为正史，必须经过作者确认。

### 3.4 记忆写入

推荐写入流程：

1. 生成或修改正文。
2. 抽取候选事实。
3. 与已有记忆比对。
4. 标记新增、修改、冲突、删除。
5. 展示给用户确认。
6. 写入对应状态。
7. 记录来源章节和生成任务。

候选事实示例：

- “林照在第 12 章得知母亲并非病死。”
- “赤月术的代价是消耗施术者近期记忆。”
- “沈微澜称呼主角为‘小先生’，不是直呼姓名。”

### 3.5 记忆读取与上下文包

每次生成不应把所有记忆塞进模型，而应构建任务相关的上下文包。

生成一章正文时，上下文包建议包含：

- 作品一句话定位。
- 当前卷目标。
- 当前章节目标。
- 前 1-3 章摘要。
- 当前场景卡。
- 出场人物状态和声音。
- 相关世界规则。
- 相关伏笔。
- 必须避免的冲突。
- 风格指南。
- 作者本轮指令。

上下文包需要可预览，便于作者发现“AI 为什么这么写”。

## 4. 工作流编排

### 4.1 标准创作闭环

标准闭环：

1. 规划：总编 agent 生成任务单。
2. 检索：系统构建上下文包。
3. 生成：主笔 agent 产出草稿。
4. 诊断：审校、伏笔、读者模拟、润色 agent 给反馈。
5. 修改：用户选择自动改写或手动编辑。
6. 确认：用户确认正文和记忆变更。
7. 回写：系统更新故事圣经、时间线、伏笔表和人物状态。
8. 复盘：生成下一章任务建议。

### 4.2 任务类型路由

- 用户说“帮我想一个设定”：路由到题材定位/世界观 agent。
- 用户说“这个人物不立体”：路由到人物 agent 和剧情结构 agent。
- 用户说“写第 8 章”：路由到总编、记忆检索、正文主笔、连续性审校。
- 用户说“这段太水”：路由到润色 agent 和读者模拟 agent。
- 用户说“检查前后矛盾”：路由到连续性审校 agent。
- 用户说“伏笔怎么回收”：路由到伏笔 agent 和剧情结构 agent。

### 4.3 人类控制点

必须有人类确认的控制点：

- 作品定位。
- 核心设定。
- 主要人物命运。
- 大纲关键转折。
- 正文发布版本。
- 记忆正史写入。
- 合规风险处理。

可自动执行的控制点：

- 草稿生成。
- 错别字和病句建议。
- 初步质量评分。
- 伏笔状态提醒。
- 上下文包推荐。

## 5. 质量评估架构

### 5.1 评估维度

建议每次章节生成后形成结构化评估：

- Continuity：与正史是否冲突。
- Motivation：人物行为是否有动机。
- Plot Progress：故事线是否推进。
- Promise Progress：题材承诺是否兑现或推进。
- Hook：开头和结尾钩子是否有效。
- Conflict：冲突是否具体、有代价、有升级。
- Style：文风和人物声音是否稳定。
- Originality：是否套路化或浅层拼贴。
- Compliance：是否有内容或版权风险。

### 5.2 评估输出

评估不应只给分，还要给：

- 问题位置。
- 为什么是问题。
- 影响范围。
- 修改建议。
- 是否需要更新记忆。

### 5.3 回归测试思路

长篇作品可以做“创作回归测试”：

- 关键设定问答：主角能力代价是什么？
- 人物状态问答：某角色目前是否知道某秘密？
- 时间线问答：某事件发生在第几章之前还是之后？
- 伏笔状态问答：哪些伏笔已埋未回收？
- 风格问答：某角色是否会使用这种称谓？

这些测试可以在每次大改后运行，类似软件工程里的回归测试。

## 6. 技术实现建议

### 6.1 存储

建议混合存储：

- 关系数据库：作品、章节、版本、任务、权限、状态。
- 文档存储：正文、设定文档、审校报告。
- 向量索引：语义检索正文、素材和记忆。
- 图数据库或关系表：人物、事件、地点、组织、伏笔之间的关系。
- 对象存储：图片、附件、导出文件。

### 6.2 上下文装配

上下文装配是系统核心能力之一，应独立成服务：

- 接收任务类型和目标。
- 读取相关正史记忆。
- 读取临近章节摘要。
- 读取相关实体和故事线。
- 控制 token 预算。
- 输出可审计的上下文包。

### 6.3 模型调用

不同任务可使用不同模型策略：

- 规划和审校：偏推理能力。
- 正文生成：偏文学表达和长文本能力。
- 抽取和分类：偏成本效率。
- 敏感内容和相似性：专门模型或规则引擎。

平台不应把模型供应商写死在业务逻辑里。

### 6.4 版本和分支

创作天然需要试错。系统应支持：

- 章节多版本。
- 大纲分支。
- 人物命运分支。
- 世界规则实验分支。
- 分支合并和废弃。

记忆也必须跟随分支隔离，避免 A 分支设定污染 B 分支。

## 7. Friday 经验的可复用抽象

在不依赖具体历史记忆的前提下，可以复用我们做 agent 产品时已经验证过的几类抽象：

- 明确任务边界：每个 agent 负责可评估的任务，不让一个大模型承担所有职责。
- 工具化状态：把“记住了什么”变成可查询、可写入、可回滚的数据，而不是隐含在对话里。
- 人类确认门：重要状态变更先提出候选，再由人确认。
- 过程可追溯：保留输入、输出、上下文、决策和版本。
- 质量闭环：生成不是终点，审校、修订、复盘、记忆回写才构成一次完整工作。

这些抽象比具体模型能力更重要，因为它们决定产品是否能支撑长周期创作。
