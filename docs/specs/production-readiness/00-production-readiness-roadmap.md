# 生产化补强总路线图

## 目标

本路线图把 P0-P6 七份阶段 spec 串成一条可执行路径，目标是让 Story Pilot 从当前 MVP 进化为可以投入真实长篇小说创作的本地优先桌面应用。

这里的“生产化”不是一次性做完所有理想能力，而是建立可发布、可恢复、可验证、可扩展的创作系统。每个阶段必须有独立可验收的产物，并且为下一阶段提供稳定基础。

## 当前版本定位

当前 `feat/mvp-implementation` 分支已经具备：

- Tauri 桌面端。
- React + Ant Design 工作台。
- NestJS TypeScript sidecar。
- SQLite 项目数据库。
- Kuzu 图谱投影雏形。
- AI ModelGateway 和 prompt/schema 基础。
- 创作路径、作品立项、蓝图、要素候选、章纲、章节草稿、记忆候选的 MVP 链路。

当前还不能定义为生产级，原因是：

- 安装包仍需强化独立运行能力。
- 阶段推进尚未完全由数据门禁驱动。
- 大纲和剧情规划还不能支撑百万字。
- 长期记忆和图谱还缺少时序、范围和连续性规则。
- 正文生产缺少批量、审稿、改写、摘要、记忆回流的完整闭环。
- 缺少长篇压测、安装 smoke、诊断和发布门禁。

更具体的生产级问题清单、阶段补强重点和不可降级项见 [生产级优化补强方案](./09-production-reinforcement-plan.md)。本路线图负责阶段顺序和里程碑，补强方案负责说明每个阶段必须解决的真实生产风险。

## 阶段目标

| 阶段 | 生产化目标                 | 完成后能力                                              |
| ---- | -------------------------- | ------------------------------------------------------- |
| P0   | 运行时、配置、发布基础稳定 | 用户安装后可以独立启动、配置模型、创建项目、备份恢复    |
| P1   | 创作路径由门禁驱动         | 阶段完成基于真实数据完整度，不再只靠按钮推进            |
| P2   | AI 能力生产化              | 所有生成都有上下文、prompt 版本、schema、审稿、产物审计 |
| P3   | 长篇规划能力成型           | 支持全书、分卷、弧线、章节、场景的滚动规划              |
| P4   | 长期记忆和图谱成型         | 人物、事件、设定、关系、伏笔可以长期追踪和校验          |
| P5   | 正文生产工作台成型         | 章纲到正文、审稿、改写、版本、记忆回流闭环可用          |
| P6   | 发布质量门禁成型           | 有完整自动化验证、长篇压测、诊断、恢复和发布标准        |

## 依赖顺序

```text
P0 runtime foundation
  -> P1 gate engine
    -> P2 AI workflow foundation
      -> P3 longform planning
        -> P4 memory and graph continuity
          -> P5 chapter production workbench
            -> P6 release gate and hardening
```

允许并行：

- P2 的 prompt 方法论调研可以和 P1 并行，但不能合入生产流程前绕过 P1 门禁。
- P3 的长篇数据模型设计可以和 P2 prompt 设计并行，但 chapter generation 必须等 P2 workflow 可审计后再接入。
- P6 的测试工具和 synthetic data generator 可以提前建设，但发布门禁必须覆盖 P0-P5 的最终接口。

不允许并行：

- P5 不能在 P3/P4 未完成时宣称支持百万字长篇，因为正文生成必须依赖 chapter plan、memory 和 graph context。
- P2 不能在 P0 未完成时默认使用 fake provider，因为生产态必须明确模型配置状态。
- P1 不能跳过上游变更影响分析，否则后续大纲和正文会被过期设定污染。

## 里程碑

### M1 内测可用

范围：P0 + P1。

能力：

- 安装包可启动。
- `~/.story-pilot` 数据目录稳定。
- 模型配置可见且可校验。
- 九步创作路径有真实门禁。

限制：

- AI 生成仍可以只覆盖部分能力。
- 长篇规划和连续性校验仍不完整。

### M2 创作流程可用

范围：P0-P3。

能力：

- 用户可以完成立项、蓝图、世界观、人物、剧情弧线、分层大纲。
- AI 产物可审计。
- 可以生成未来 10-20 章可用章纲。

限制：

- 记忆和图谱连续性还不能完全承诺长期一致。

### M3 长篇创作可用

范围：P0-P5。

能力：

- 支持从章纲生产正文。
- 支持生成后审稿、局部改写、版本管理、记忆抽取、用户确认和图谱回流。
- 支持至少 10 章连续创作闭环。

限制：

- 发布前仍需通过 P6 门禁，才能对外作为生产版本分发。

### M4 生产发布候选

范围：P0-P6。

能力：

- 通过完整 CI、安装包 smoke、百万字 synthetic 压测、诊断和恢复演练。
- 可以向真实创作者开放生产试用。

## 每阶段完成定义

每个阶段必须同时满足：

- Spec 中所有 API、数据模型、流程和 UI 入口已实现或明确废弃并更新 spec。
- 对应阶段的“生产级补强重点”和“不可降级项”全部通过验收。
- 覆盖单元测试、集成测试和至少一条 E2E/smoke 测试。
- 关键错误路径有测试。
- 数据迁移有测试。
- 文档索引和用户可见行为一致。
- 已完成 `pnpm lint`、`pnpm typecheck`、`pnpm test`。
- 如涉及桌面壳或打包，完成 Tauri 检查和 DMG 验证。

## 执行方式

后续开发建议每个 P 阶段单独开实施计划，并按任务切片提交：

```text
P0 plan -> P0 tasks -> P0 verification -> P0 commit
P1 plan -> P1 tasks -> P1 verification -> P1 commit
...
P6 plan -> P6 tasks -> P6 verification -> P6 commit
```

单个提交不应同时跨越多个 P 阶段，除非只是共享类型或测试工具。跨阶段接口变更必须同步更新关联 spec 和追踪矩阵。

## 风险控制

| 风险               | 影响               | 控制策略                                 |
| ------------------ | ------------------ | ---------------------------------------- |
| 过早追求聊天 Agent | 稀释生产工作台能力 | UI 默认工作台，AI 通过任务和产物体现     |
| 大纲直接跳正文     | 长篇因果断裂       | P3 先完成分层大纲，P5 才开放章纲驱动正文 |
| 记忆自动入 canon   | 设定污染           | 所有 AI 记忆必须候选化，用户确认后入库   |
| 图谱只做展示       | 无法保证连续性     | P4 引入规则引擎和生成前后校验            |
| 安装包依赖开发环境 | 用户无法启动       | P0 优先解决 sidecar 独立运行             |
| prompt 无评测      | 改动不可控         | P2 建立离线 eval 和人工评审门禁          |
