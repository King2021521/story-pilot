# 生产级优化补强方案

## 目标

把前面产品、架构和当前实现分析收敛成一套可执行的生产级补强方案。本文回答三个问题：

- 当前版本为什么还不能称为生产级。
- 要补哪些能力才能支撑真实创作者持续创作百万字长篇小说。
- 每个阶段的交付边界、不可降级项和验收证据是什么。

本文不替代 P0-P6 阶段 spec，而是作为阶段实施的总控说明。具体实现细节以各阶段 spec 为准。

## 生产级结论

当前 Story Pilot 更接近“可演示的本地创作 MVP”，还不是可投入生产使用的长篇小说创作平台。

它已经证明了核心方向：本地优先桌面端、NestJS sidecar、SQLite/Kuzu 存储、创作路径、AI 产物和记忆候选可以连起来。但对真实创作者而言，生产级标准不是“能生成一次内容”，而是：

- 连续写作数月时数据不能丢。
- 上百万字项目打开、检索、规划仍然稳定。
- AI 生成结果能被审阅、追溯、回滚和复用。
- 设定、人物、事件、伏笔、关系、章节之间不会越写越乱。
- 创作者能从立项一路走到正文生产、记忆确认、复盘和下一批章节。

因此，生产化补强必须优先解决“闭环能力”，而不是继续堆单点生成按钮。

## 生产级问题清单

| 问题域         | 当前风险                                     | 生产影响                                | 对应阶段 |
| -------------- | -------------------------------------------- | --------------------------------------- | -------- |
| 运行与发布     | 安装包、sidecar、配置、数据目录仍需硬化      | 用户安装后启动失败或依赖开发环境        | P0       |
| 创作流程闭环   | 阶段切换仍可能绕过真实数据完整性             | 世界观、人物、大纲、正文之间断流        | P1       |
| AI 能力封装    | 生成能力、prompt、schema、审稿未完全统一     | AI 输出不可评估，改 prompt 后质量不可控 | P2       |
| 长篇规划       | 大纲粒度不足，缺少全书/分卷/弧线/场景分层    | 无法支撑百万字连载，只能写短篇或样章    | P3       |
| 记忆与知识图谱 | 记忆证据、有效范围、冲突规则、增量图谱不完整 | 人物状态、关系、设定和伏笔长期失真      | P4       |
| 正文生产       | 草稿、diff、改写、版本、摘要、记忆回流不完整 | 用户无法形成可持续生产章节的日常工作流  | P5       |
| 质量与发布门禁 | 缺少长篇压测、安装 smoke、恢复演练和发布标准 | 不能判断版本是否真的能给创作者稳定使用  | P6       |

## 阶段补强总览

| 阶段 | 补强主题               | 必须交付                                                  | 阶段出口                                             |
| ---- | ---------------------- | --------------------------------------------------------- | ---------------------------------------------------- |
| P0   | 可安装、可启动、可恢复 | `~/.story-pilot` 契约、模型设置、诊断、备份、安装 smoke   | 干净机器安装启动成功，未配置模型时不生成假内容       |
| P1   | 创作路径数据门禁       | 九步 gate report、strict/force/skip/reopen、下游影响分析  | 用户能从立项推进到世界观、人物、剧情、大纲且不卡死   |
| P2   | AI 工作流生产化        | capability registry、prompt 版本、schema、model call 审计 | 每次 AI 输出都有上下文、提示词版本、产物和评测证据   |
| P3   | 长篇剧情与大纲引擎     | Book/Volume/Arc/Chapter/Scene plan、滚动规划、影响分析    | 支持 1000 章规划结构和未来 10-20 章详细章纲          |
| P4   | 记忆与图谱连续性       | Memory V2、增量图谱、连续性规则、混合检索上下文           | 生成前后都能检查人物、设定、事件、伏笔关系           |
| P5   | 正文生产工作台         | 章纲到正文、artifact diff、局部改写、版本、摘要、记忆回流 | 用户能连续完成至少 10 章生产、审稿、保存和下一章准备 |
| P6   | 发布质量门禁           | verify 脚本、DMG smoke、百万字 synthetic、性能预算        | 发布候选通过自动化、人工验收和恢复演练               |

## P0 运行时和发布基础补强

P0 的核心不是“能在开发机跑起来”，而是“用户机器上稳定跑起来”。

必须补强：

- sidecar 必须作为安装包内受控二进制启动，不依赖源码仓库、全局 Node 或全局 pnpm。
- `~/.story-pilot/setting.json` 是唯一用户可编辑配置入口，包含模型、存储和隐私配置。
- `~/.story-pilot/projects/<projectId>` 是每个作品的唯一数据根，SQLite、Kuzu、导出、附件、备份都在项目目录下。
- 模型未配置时，所有 AI 入口都必须显示配置缺口，不允许使用 fake provider 冒充真实生成。
- 备份恢复、诊断导出、日志脱敏必须先完成，否则长篇创作没有数据安全基础。

不可降级项：

- 任何日志、诊断、错误输出都不能包含完整 API key。
- 任何文件读写都不能越过应用数据目录和用户显式授权目录。
- 数据库损坏时不能自动覆盖原文件，必须先保留现场并提供恢复入口。

对应 spec：[P0 运行时、配置与发布基础 Spec](./01-runtime-config-release-spec.md)。

## P1 创作路径门禁补强

P1 要解决用户当前已经遇到的问题：某一步完成后，如果下一步没有明确入口和补齐标准，创作流程就会卡住。

必须补强：

- 九步创作路径必须由 gate report 驱动，而不是由按钮点击硬切状态。
- 每个阶段都要能解释“为什么不能进入下一步”，并给出具体补齐入口。
- `作品立项 -> 创作蓝图 -> 世界观 -> 人物 -> 剧情弧线 -> 大纲设计 -> 章节生产 -> 记忆校验 -> 阶段复盘` 必须成为闭环路径。
- 上游核心数据变更后，下游阶段必须标记 `needs_revision`，防止旧大纲继续驱动正文。
- `force` 和 `skip` 只作为有审计的专家操作，不能成为默认路径。

不可降级项：

- 不能只在前端判断阶段状态，后端必须以数据库事实计算门禁。
- 不能把“用户点了确认”当成“内容完整”，必须校验关键结构化数据。
- 不能让任意阶段没有补齐入口。

对应 spec：[P1 创作门禁与阶段数据完整性 Spec](./02-creative-gates-data-integrity-spec.md)。

## P2 AI 工作流补强

P2 要把 AI 从“几个调用函数”提升为“可审计、可评估、可迭代的创作生产系统”。

必须补强：

- 所有正式 AI 能力都通过 capability registry 暴露，不能散落在各 service 里直接调模型。
- 每个 capability 必须绑定系统提示词、输出 schema、prompt version、评测 fixture 和产物类型。
- 每次模型调用必须保存 prompt version、context package、request metadata、response metadata、schema 校验结果和错误信息。
- AI 输出默认进入 artifact、candidate 或 review，不直接写 canon。
- 系统提示词必须覆盖网络小说方法论：题材承诺、人物动机、冲突升级、爽点/悬念/情绪回报、章末钩子、长线伏笔和平台读者预期。

不可降级项：

- 不允许生产态静默降级为 fake provider。
- 不允许 schema 校验失败的内容进入用户可采纳流程。
- 不允许 prompt 改动没有 hash、version 和 eval 证据。

对应 spec：[P2 AI 工作流、提示词与评测体系 Spec](./03-ai-workflow-prompt-evaluation-spec.md)。

## P3 长篇剧情和大纲引擎补强

P3 是能否支撑百万字长篇的分水岭。百万字创作不能靠一次性大纲，也不能靠每章临时生成。

必须补强：

- 建立 Book Plan、Volume Plan、Arc Plan、Chapter Plan、Scene Plan 五层规划。
- 剧情弧线、人物弧线、冲突、伏笔、世界规则必须成为章纲生成硬输入。
- 采用滚动规划：全书低频稳定，当前卷中等细节，未来 10-20 章高细节。
- 大纲变更必须输出影响分析，定位受影响人物、事件、伏笔和章节。
- 章节生产必须绑定已通过 gate 的 chapter plan。

不可降级项：

- 不能用固定 10 章模板代表长篇规划能力。
- 不能只存自然语言大纲，必须存结构化字段和引用关系。
- 不能绕过剧情线和人物弧线直接生成正文。

对应 spec：[P3 长篇大纲与剧情引擎 Spec](./04-longform-outline-plot-engine-spec.md)。

## P4 记忆和知识图谱补强

P4 要让长期记忆从“文本片段集合”变成“可验证的创作事实系统”。

必须补强：

- 记忆必须有来源、证据、范围、有效章节、状态、置信度、取代关系和冲突分组。
- 图谱必须覆盖人物、关系、事件、地点、物品、组织、世界规则、伏笔和章节计划。
- 图谱投影要支持增量更新，全量 rebuild 只作为修复命令。
- 连续性规则必须覆盖硬冲突：死亡后行动、物品双归属、世界规则违反、伏笔回收顺序错误、事件因果环等。
- 章节生成前的上下文必须来自混合检索：结构化图谱、FTS、embedding、最近摘要和关键 canon。

不可降级项：

- 不能让 AI 自动把候选记忆写成 canon。
- 不能把图谱只做成展示关系图，必须参与生成前后校验。
- 不能把 hypothesis 当作事实传给正文生成。

对应 spec：[P4 长期记忆与知识图谱一致性 Spec](./05-memory-knowledge-graph-continuity-spec.md)。

## P5 正文生产工作台补强

P5 要让产品进入真实日常创作：不是生成一段样例，而是每天稳定推进章节。

必须补强：

- 正文生成入口必须从 chapter plan 进入，生成前先构建 context package。
- AI 草稿以 artifact 形式预览，支持 diff、应用全部、应用选中段落和拒绝。
- 局部改写支持润色、扩写、压缩、增强冲突、增强钩子、人物语气修复、连续性修复。
- 应用草稿或 patch 必须创建 chapter version。
- 应用正文后必须生成章节摘要、记忆候选，并触发图谱增量投影。
- 批量生产支持 3/5/10 章，但默认停在用户审稿节点。

不可降级项：

- AI 不能直接覆盖用户正文。
- 没有版本和恢复能力时不能开放批量生产。
- 未完成摘要和记忆回流时，下一章上下文不能标记为 ready。

对应 spec：[P5 正文生产与创作者编辑工作台 Spec](./06-chapter-production-editor-spec.md)。

## P6 发布质量门禁补强

P6 要把“我本机能跑”变成“这个版本可以交给真实用户”。

必须补强：

- 统一 `pnpm verify`、`verify:package`、`verify:longform`。
- DMG 构建后必须验证安装包、首次启动、重启恢复和 sidecar health。
- synthetic project 必须覆盖百万字量级：1000 章、10000 记忆、5000 事件、800 伏笔。
- 性能预算必须覆盖启动、打开项目、章节树、记忆检索、图谱查询、context package 和章节保存。
- 恢复演练必须覆盖 SQLite 损坏、Kuzu 重建、备份恢复和诊断导出。

不可降级项：

- 没有通过安装 smoke 的 DMG 不能作为发布候选。
- 没有长篇 synthetic 压测不能宣称支撑百万字。
- 诊断包不能包含完整正文、完整 prompt、完整模型响应或完整 API key。

对应 spec：[P6 生产 QA、性能、观测与发布门禁 Spec](./07-production-qa-performance-ops-spec.md)。

## 生产级 E2E 闭环

最终验收必须覆盖一条真实创作路径：

```text
首次启动
配置模型
创建作品
完成作品立项
生成并应用创作蓝图
生成并采纳世界观要素
生成并采纳人物和关系
生成剧情弧线、冲突和伏笔
生成全书规划、分卷规划和未来 10-20 章章纲
从第 1 章章纲生成正文 artifact
审阅质量和连续性问题
局部改写并应用正文
保存章节版本
抽取并确认记忆候选
增量投影图谱
进入第 2 章并确认上下文引用第 1 章变化
重启应用并确认项目完整恢复
创建备份、恢复备份、导出脱敏诊断包
```

这条链路不通过，就不能定义为生产级。

## 阶段实施原则

- P0-P2 是生产化地基，必须先完成再大规模开发 P3-P5。
- P3-P5 是创作者核心价值，必须围绕“长篇闭环”设计，而不是围绕单个生成按钮。
- P6 是发布门槛，不是文档补充；每个发布候选都必须跑。
- 每个阶段都要先写失败测试，再实现，再补集成和 E2E。
- 每个阶段完成后更新 [生产化测试验证与追踪矩阵](./08-validation-traceability-matrix.md)。

## 完成定义

当且仅当满足以下条件，Story Pilot 才能作为生产试用版交付：

- P0-P6 所有验收标准通过。
- 生产级 E2E 闭环通过。
- 百万字 synthetic project 通过性能预算。
- 真实模型评审至少覆盖玄幻、都市、悬疑三个题材样本。
- 所有 AI 输出均可追溯到 prompt version、context package、model call 和 artifact。
- 所有 canon 数据均有来源、状态和变更审计。
- 用户可恢复最近一次有效项目状态。
